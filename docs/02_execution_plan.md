# خطة التنفيذ المرحلية لـ OmniTune Engine

## المرحلة 1: التأسيس (الحالية)
1. إنشاء هيكل مجلدات طبقي واضح.
2. تعريف العقود الأساسية:
   - `BaseDataLoader`
   - `BaseModelTrainer`
3. بناء `MockDataLoader` لتحويل البيانات إلى ChatML.
4. بناء `UnslothTrainer` أولي لتهيئة LoRA/QLoRA.
5. إنشاء واجهة API تستقبل طلب التدريب وتنفذه بالخلفية.

## المرحلة 2: الربط الحقيقي بالمصادر
1. إضافة محولات بيانات فعلية (JSON/SQL/PDF/Vector DB).
2. توحيد مخطط البيانات الداخلة لكل محول.
3. إضافة تحقق جودة البيانات والتنظيف قبل التحويل.

## المرحلة 3: تنفيذ التدريب الكامل
1. ربط Unsloth مع دورة تدريب فعلية.
2. إدارة checkpoints والتخزين.
3. دعم استئناف التدريب واسترجاع الحالة.

## المرحلة 4: صف مهام إنتاجي
1. نقل التنفيذ الخلفي إلى Celery + Redis.
2. إضافة retry policy وحدود الموارد.
3. عزل مهام التدريب عن واجهة API عبر workers مستقلة.

## المرحلة 5: المراقبة والحوكمة
1. إضافة قياس شامل (زمن/ذاكرة/نجاح/فشل).
2. تتبع التجارب (Experiment Tracking).
3. سياسات أمان للمدخلات والملفات الحساسة.

## المرحلة 6: النشر والتوسع
1. حاويات Docker لكل خدمة.
2. إعداد CI/CD للتحقق والنشر.
3. إضافة طبقة إدارة متعددة المشاريع والعملاء.
